## 🤖 Использование ИИ в процессе разработки

В ходе выполнения тестового задания ИИ-ассистент использовался как инструмент поддержки разработки: для уточнения архитектурных решений, отладки, тестирования и оформления проекта.

ИИ применялся на следующих этапах:

---

### 🏗 Проектирование backend-архитектуры

Использовался для уточнения структуры REST-сервиса, организации слоёв приложения (Controller → Service → Mapper), а также разделения бизнес-логики и слоя доступа к данным.

**Пример запроса:**

> “Как правильно организовать структуру REST API проекта с использованием Spring Boot и MyBatis, чтобы соблюсти слоистую архитектуру?”

---

### 🐳 Настройка Docker и базы данных PostgreSQL

Использовался для решения проблем с запуском Docker Compose и корректной настройкой окружения, чтобы приложение запускалось “из коробки”.

**Пример запроса:**

> “Как правильно организовать запуск PostgreSQL через Docker Compose так, чтобы проект корректно стартовал у других разработчиков без дополнительных настроек?”

---

### 🧪 Реализация unit-тестов (JUnit + Mockito)

Использовался для проектирования unit-тестов сервисного слоя и корректной настройки моков для зависимостей.

**Пример запроса:**

> “Как правильно покрыть сервисный слой unit-тестами с использованием JUnit 5 и Mockito, включая проверку исключений?”

---

### ❗ Реализация обработки исключений

Использовался для проектирования централизованной обработки ошибок через `@RestControllerAdvice` и стандартизации формата ответов API.

**Пример запроса:**

> “Как правильно реализовать глобальную обработку исключений в Spring Boot через @RestControllerAdvice с единым форматом ErrorResponse?”

---

### 📦 Интеграция Postman и документация API

Использовался для подготовки Postman-коллекции и оформления README с инструкцией запуска проекта и проверки API.

**Пример запроса:**

> “Как правильно экспортировать Postman collection и environment, чтобы их можно было добавить в GitHub проект для удобной проверки API?”
